# Repo Review - 2026-04-08

## Critique

This repository provides a solid foundation for managing AI agent context through Frequent Intentional Compaction (FIC). However, it currently suffers from several inconsistencies and incomplete sections that hinder its effectiveness.

### Strengths
- **Structured Methodology**: Clear emphasis on TDD, small steps, and frequent context resets.
- **Agent-Specific Guidance**: Detailed instructions for different agents (Claude, Cursor, Gemini) are highly valuable.
- **Modular Rules**: Categorizing rules into `.rules/` makes them easier to manage.

### Weaknesses
- **Redundancy and Fragmentation**: Multiple identical "entry point" files (`AGENTS.md`, `GEMINI.md`, `.rules/entry.md`) create confusion and maintenance overhead.
- **Incomplete Core Content**: The `README.md` has a `// TODO` for the FIC workflow explanation, which is the central theme of the repo.
- **Language Inconsistency**: Significant portions of the `README.md` are in Spanish, contradicting the "English-Only" rule in `.rules/base-rules.md`.
- **Documentation Drift**: `PROJECT.md` is a generic template and doesn't accurately describe *this* repository.
- **Missing Rules**: The "Context reset rule" recommended in `README.md` is not actually present in `.rules/base-rules.md`.
- **Non-Portable Config**: `settings.json` contains absolute system paths, making it unusable for other users.
- **Structural Mismatch**: The repo mentions a `.docs/` directory that does not exist.

---

## Improvement Plan

### 1. Unified Entry Point and Structure
- **Action**: Designate `AGENTS.md` as the primary entry point and remove redundant files (`GEMINI.md`, `.rules/entry.md`).
- **Action**: Create the missing `.docs/` directory to hold stable, human-readable documentation.
- **Action**: Clear up or act upon `.rules/TODO-REFACTOR-profiles`.

### 2. Documentation and Language Standardization
- **Action**: Translate all Spanish content in `README.md` to English.
- **Action**: Complete the `// TODO` section in `README.md` with a clear explanation of the FIC workflow.
- **Action**: Rename the current `PROJECT.md` to `PROJECT_TEMPLATE.md` and create a dedicated `PROJECT.md` that describes this specific configuration repo.

### 3. Rule Synchronization and Refinement
- **Action**: Add the "Context reset rule" from `README.md` directly into `.rules/base-rules.md`.
- **Action**: Update `settings.json` to be more portable or document how to configure it locally without hardcoded paths.

### 4. Workflow Enhancements
- **Action**: Provide markdown templates in `.thoughts/` for research, plans, and validation to help agents follow the FIC workflow consistently.
- **Action**: Explicitly link all rule files in the primary entry point (`AGENTS.md`) so agents can discover them easily.
